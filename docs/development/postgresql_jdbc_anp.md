# ANP PostgreSQL → Databricks Bronze

## Objective

Document the ANP fuel-price ingestion path from local CSV files into PostgreSQL and from PostgreSQL into the Databricks Bronze layer.

## Architecture

```text
ANP CSV files
    ↓
AnpCombustiveisLoader
    ↓
PostgreSQL
    ├── anp.combustiveis_precos
    └── platform.ingestion_control
    ↓ JDBC
AnpCombustiveisPostgresReader
    ↓
BronzeWriter.replace_where
    ↓
prd.bronze.anp_combustiveis_precos
```

PostgreSQL is used as an operational source for the ANP dataset. GitHub remains the source of truth for code and migrations. Databricks consumes PostgreSQL through JDBC and materializes Delta Bronze data.

## PostgreSQL ingestion

The loader imports ANP CSV files through PostgreSQL `COPY`, converts the source text fields into the target types, and records the successful load in `platform.ingestion_control`.

Each row persisted in `anp.combustiveis_precos` keeps `source_file` so file-level lineage is not lost after the CSV is loaded into PostgreSQL.

The file hash is used to avoid loading the same file twice.

## PostgreSQL schema bootstrap

Versioned SQL scripts live under `infra/postgres/init` and are executed in lexical order by `postgres_bootstrap`.

Current scripts:

- `001_create_schemas.sql`
- `002_create_anp_tables.sql`
- `003_create_ingestion_control.sql`
- `004_add_anp_source_file.sql`

The bootstrap is intentionally idempotent so the same mechanism can prepare Docker PostgreSQL and Azure Database for PostgreSQL.

## JDBC layer

`platform.jdbc` is generic and does not contain ANP-specific rules.

`AnpCombustiveisPostgresReader` owns the source table and ANP date-slice query. It pushes the requested `data_coleta` interval down to PostgreSQL instead of reading the complete table and filtering in Spark.

Additional Bronze metadata:

- `dt_base = data_coleta`
- `source_system = azure_postgresql`
- `source_file` is preserved from PostgreSQL
- `ingestion_timestamp` is added by `BronzeWriter`

## Bronze contract

Target table:

```text
prd.bronze.anp_combustiveis_precos
```

The Bronze contract uses:

- technical primary key: `id`
- clustering: `dt_base`
- write strategy: `REPLACE_WHERE`

`id` is the technical identity generated by PostgreSQL. It is not treated as a business key.

## Reprocessing and idempotency

The job receives an explicit date interval. The same interval is used both for JDBC predicate pushdown and for the Delta `replaceWhere` predicate.

Example:

```text
2016-01-04 → 2016-06-30
```

The validated reprocessing predicate is:

```sql
dt_base >= DATE '2016-01-04'
AND dt_base <= DATE '2016-06-30'
```

Reprocessing the same interval was validated to preserve the same final state:

- rows: 486897
- distinct ids: 486897
- minimum `dt_base`: 2016-01-04
- maximum `dt_base`: 2016-06-30
- `source_file`: ca-2016-01.csv
- null `source_file`: 0

## Credentials and least privilege

Databricks does not use the PostgreSQL administrator account.

The dedicated PostgreSQL role is:

```text
olist_databricks_reader
```

Required access is limited to database connection, schema usage, and table select privileges.

JDBC credentials are stored in the Databricks secret scope:

```text
olist-jdbc
```

Keys:

- `username`
- `password`

Secrets must never be committed to the repository or stored directly in notebooks.

## Databricks serverless networking

The active project workspace runs on Databricks AWS in `us-east-2` and uses serverless compute.

A serverless workload does not have one stable egress IP. Azure PostgreSQL firewall rules therefore use the official Databricks outbound prefixes for:

```text
platform = aws
region   = us-east-2
service  = Databricks
type     = outbound
```

Prefixes observed and configured during this implementation:

```text
18.221.200.169/32
3.128.237.208/28
3.145.247.0/24
```

These ranges are external platform data and can change. Their maintenance should eventually be automated instead of relying on manual firewall updates.

## Troubleshooting lessons

### Databricks secrets and PowerShell

Do not pipe single-line secret values into `databricks secrets put-secret` from PowerShell. The pipe introduced CRLF characters in the username and resulted in a value equivalent to:

```text
olist_databricks_reader\r\n
```

Use `--string-value` or interactive input for single-line secrets.

A SCRAM error containing `SaslPrep` and `Prohibited character` is a strong signal to inspect credential control characters before changing network configuration.

### Diagnose JDBC by layer

Use the error transition to isolate the failing layer:

1. connection timeout / failed connection → network, routing, firewall
2. PostgreSQL authentication error → network path and driver are already working; inspect credentials
3. permission error → authentication worked; inspect grants
4. SQL/query error → connection and permissions are already established

Validate PostgreSQL credentials locally with Psycopg before debugging the same credential in Databricks.

### Serverless cache behavior

The ANP Bronze job must not call `DataFrame.cache()` or `persist()` because Databricks serverless rejected table persistence with `NOT_SUPPORTED_WITH_SERVERLESS`.

The job intentionally performs the count and write without explicit DataFrame persistence.

### Serverless firewall behavior

Do not build PostgreSQL firewall rules around the IP returned by `api.ipify.org` from one serverless execution. The observed IP can change between executions.

Use the official serverless outbound prefixes for the workspace cloud and region.

### PostgreSQL migrations

When adding lineage to an already populated PostgreSQL table, first verify `platform.ingestion_control` before performing a backfill. For the first ANP load, the control table proved that all existing rows originated from `ca-2016-01.csv`, allowing a controlled backfill followed by `SET NOT NULL`.

### pytest module-name collisions

Multiple tests named `test_config.py` in different directories caused pytest import-file mismatch errors with the default import behavior.

The project uses:

```toml
addopts = ["--import-mode=importlib"]
```

This allows repeated test basenames while preserving the directory-based organization.

Unit tests that verify environment defaults must explicitly clear optional environment variables so developer credentials exported in the shell cannot leak into test behavior.
